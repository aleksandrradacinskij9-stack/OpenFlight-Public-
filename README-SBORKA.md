# OpenFlight 0.05 — первый работающий Android-прототип

**Ту-154М • Домодедово (UUDD) • ВПП 14/32 • Vulkan • C++17**

Первый прототип по концепции проекта (разделы 11 и 45): маленькая, но реально
работающая версия, в которой уже есть небо, облака, земля, аэропорт с ВПП и
разметкой, самолёт-заглушка, камера, сенсорное управление и базовая физика полёта.

> Правило проекта выполняется: это НЕ весь OpenFlight, это минимальная рабочая
> основа, от которой будем двигаться этапами.

---

## 1. Что уже умеет эта версия

| Этап из концепции | Что сделано |
|---|---|
| 0.01 | Android-приложение запускается |
| 0.02 | 3D-сцена на Vulkan (свои шейдеры, туман, освещение) |
| 0.03 | Ту-154М (low-poly заглушка из примитивов: фюзеляж, стреловидные крылья, Т-образный хвост, 3 двигателя, шасси) |
| 0.04 | Сенсорное управление: джойстик, РУД, кнопки, 3 камеры |
| 0.05 | Базовая физика полёта: подъёмная сила, сопротивление, сваливание, закрылки, шасси, тормоза, руление |

Мир: ВПП 14/32 (3800 × 60 м, курс 140°) с осевой, пороговыми полосами, зонами
приземления; параллельная рулёжная дорожка с соединениями; перрон; терминал,
вышка, ангары; облака; земля 80 × 80 км с туманом на горизонте.

Физика посчитана по реальным данным Ту-154М: масса 78 т (заправка ~50%),
площадь крыла 201,45 м², тяга 3 × Д-30КУ-154 (103 кН). Проверка численным
моделированием (файл `preview/physics_takeoff.png` в выдаче):
- разбег до Vr = 235 км/ч — **630 м**, отрыв на ~21-й секунде;
- скороподъёмность после уборки шасси — **~15-17 м/с**;
- сваливание с закрылками 45° — **~185 км/ч**, чистое крыло — ~230 км/ч.

## 2. Быстрый старт: готовый APK (2 минуты, ПК не нужен)

1. Перекиньте файл **`OpenFlight-0.05-debug.apk`** на телефон (мессенджер, кабель, облако — как угодно).
2. Откройте файл на телефоне. Android спросит разрешение — разрешите
   «установку из неизвестных источников» для того приложения, через которое открываете.
3. Если Google Play Protect предупредит о неизвестном приложении —
   «Подробнее» → «**Всё равно установить**» (это наш прототип, он ничего не просит: никаких разрешений у приложения нет вообще).
4. Запустите **OpenFlight**. Поверните телефон горизонтально — игра сама в ландшафте.

**Требования к телефону:** Android 7.0+ и поддержка Vulkan (любой смартфон
примерно 2016 года и новее; сборка под arm64). Если приложение сразу
закрывается с сообщением про Vulkan — пришлите модель телефона, добавим
резервный GLES-рендерер (он и так запланирован в концепции как запасной).

## 3. Сборка из исходников (Android Studio на ПК)

Понадобится: ПК (ваш i3-12100 справится легко), интернет ~500 МБ трафика,
Android Studio (https://developer.android.com/studio → «Download Android Studio»).

1. Распакуйте папку `OpenFlight` из архива `OpenFlight-0.05-project.zip` в удобное место
   (путь без русских букв и пробелов, например `D:\dev\OpenFlight`).
2. Android Studio → **Open** → выберите папку `OpenFlight`.
3. Дождитесь Gradle Sync (первый раз качает зависимости, 5–15 минут).
   Всё необходимое (SDK 34, NDK 26.3, CMake) студия предложит установить сама — соглашайтесь.
4. Включите на телефоне «Для разработчиков» → «Отладка по USB», подключите кабелем,
   разрешите отладку.
5. Нажмите зелёный **▶ Run**. Приложение соберётся и запустится на телефоне.

Собрать APK без телефона: **Build → Build App Bundle(s) / APK(s) → Build APK(s)**,
готовый файл появится в `app/build/outputs/apk/debug/`.

Сборка из консоли (без студии): нужен JDK 17, Android SDK (platform 34,
build-tools 34.0.0, NDK 26.3.11579264, CMake 3.22.1), затем:

```
gradle assembleDebug
```

## 4. Управление

| Элемент | Действие |
|---|---|
| **Джойстик слева** | На земле — руление носовой стойкой. В воздухе — крен (влево/вправо) и тангаж (вниз = штурвал на себя = подъём носа) |
| **ТЯГА справа** | РУД 0–100 %. Палец ставит ползунок |
| **ШАССИ: ВЫП/УБР** | Уборка/выпуск шасси (анимация ~3 с) |
| **ЗАКРЫЛКИ +/−** | Положения 0° / 15° / 28° / 45° |
| **ТОРМОЗА** | Колёсные тормоза (зелёная надпись = включены) |
| **КАМ** | ЧЕЙЗ → КАБИНА → ВЫШКА ДМД |
| **◄ РУЛЬ / РУЛЬ ►** | Руль направления (педали), держать нажатой |
| **Палец по экрану** (вне кнопок) | Облёт камеры вокруг самолёта (ЧЕЙЗ): тянуть вправо — правый борт, вниз — камера выше |
| **Двойной тап по экрану** | Сброс камеры за хвост самолёта |

HUD слева сверху: СКОРОСТЬ, ВЫСОТА, ВАРИО (вертикальная скорость), КУРС, ТЯГА,
ЗАКРЫЛКИ, ШАССИ + предупреждения «СВАЛИВАНИЕ», «ЖЁСТКАЯ ПОСАДКА», «ЗЕМЛЯ».

## 5. Первый полёт (пошагово)

1. Самолёт стоит на пороге ВПП 14, двигатели на малом газе.
2. ТЯГА → **100 %**. Ждите ~10 секунд — Д-30 раскручиваются не мгновенно (это честно).
3. На **235–245 км/ч** плавно тяните джойстик **вниз**. Отрыв произойдёт сам.
4. Варио устойчиво «+» → **ШАССИ: УБР** (не ниже 100 м высоты).
5. Набирайте высоту: 300–400 км/ч, варио около +15 м/с. Не задирайте нос
   выше ~15° — иначе сваливание (HUD предупредит).
6. Посадка: закрылки 28°, к ВПП 32 заходите на ~280–300 км/ч, выравнивание,
   касание без вертикальной скорости, тормоза, закрылки 45° не нужны пока не освоитесь.
7. Жёсткое касание (>6,5 м/с) HUD запомнит и покажет предупреждение —
   это задел под систему повреждений (этап 5 концепции).

**Что должно быть на экране при запуске:** голубое небо с градиентом, зелёная
равнина, серая ВПП с белой разметкой уходящая к горизонту, белый Ту-154М с
синей полосой впереди, HUD на русском, кнопки и джойстик. Посмотрите
`preview/scene_chase.png` и `preview/scene_tower.png` — это рендер той же
геометрии, ориентир «как должно выглядеть».

## 6. Как устроен проект (все файлы)

```
OpenFlight/
├── README-SBORKA.md              ← этот файл
├── settings.gradle               какие модули собирать
├── build.gradle                  версия AGP
├── gradle.properties             память JVM для сборки
├── gradle/wrapper/…              версия Gradle (8.7)
└── app/
    ├── build.gradle              настройки приложения (SDK 34, NDK, arm64)
    └── src/main/
        ├── AndroidManifest.xml   ландшафт, Vulkan обязателен, без разрешений
        ├── java/com/openflight/sim/
        │   ├── MainActivity.java   окно, surface, кнопки, HUD, JNI-вызовы
        │   ├── JoystickView.java   виртуальный джойстик
        │   └── ThrottleView.java   слайдер тяги
        ├── cpp/                    ← ДВИЖОК (C++17, Vulkan)
        │   ├── CMakeLists.txt      сборка нативной библиотеки
        │   ├── math3d.h            векторы, матрицы, ориентация тела
        │   ├── mesh.h              конструктор геометрии (квады, цилиндры, призмы)
        │   ├── world.h/.cpp        мир UUDD: земля, ВПП+разметка, РД, перрон, здания, облака
        │   ├── aircraft.h/.cpp     Ту-154М: фюзеляж, крылья, хвост, двигатели, шасси, тень
        │   ├── physics.h/.cpp      физика полёта и земли (см. раздел 1)
        │   ├── vulkan_renderer.h/.cpp  Vulkan: swapchain, конвейеры, кадр
        │   ├── shaders_spv.h       шейдеры, скомпилированные в SPIR-V
        │   ├── engine.h/.cpp       поток рендера, камеры, телеметрия
        │   └── jni_entry.cpp       мост Java ↔ C++
        └── res/                    макет экрана, стили, иконки
```

Соответствие архитектуре из раздела 35 концепции: Rendering (vulkan_renderer),
Physics (physics), World (world), Aircraft (aircraft) — уже разделены на
модули; Damage, Weather, Mods, Scenarios добавим следующими этапами в эту же
структуру.

## 7. Что дальше (Этап 2 по концепции — самолётные системы)

Предлагаю порядок: двигатели с реальной запускаемой логикой (запуск/останов,
температура), топливо, электрика → потом Этап 3 погода (ветер уже заложен
в физику местом под него). Но сначала — проверяем этот прототип на вашем
телефоне и чиним всё, что не заработает.

**Если что-то не работает — сначала чиним текущую версию, а не добавляем новое
(правило из конца концепции).** Пришлите: что делали, что видите, модель
телефона; если собираете сами — текст ошибки из Android Studio или вывод
`adb logcat`.

## 8. Известные упрощения версии 0.05

- Модель самолёта — временная заглушка из примитивов (раздел 9 концепции это разрешает).
- Ветра нет (переменные под него в физике уже есть), погода — этап 3.
- Нет цифр «14»/«32» на ВПП, огней и рулёжных знаков — добавим с текстурами.
- Шасси убираются «телескопом», а не по реальной кинематике.
- Разбег получился короче реального (~630 м против ~900-1300 м) — из-за
  тестовой массы 78 т и полного газа; подкрутим на этапе систем двигателя.
- Отрицательная перегрузка и полный переворот через петлю не предусмотрены —
  углы ограничены, как у пилотируемого лайнера.
